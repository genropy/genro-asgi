## Objective
Two defects of the dbevents transport with more than one worker, both ratified as decisions in `temp/`: (D1) the worker's source filter `subscribed_tables` is refreshed only by the replies of the calls the worker itself makes, so a worker that did not subscribe — or was just born, or hosts a page woken from the freezer — filters with a stale set and drops commits nobody else can recover; (D2) the deposits of a request leave the worker only inside `collect_page`, which only the `pageCall` envelope reaches, so a request that commits without it (a `rootPage` webhook, a request failing after its commit) never delivers. After this plan the commander pushes the set to every worker on every transition of the global set, and every request delivers what its slot still holds before it returns.
